# 织文输入法 0.1.0-beta.26

本版本撤掉面板里的搜索——连同点开后铺出的那副迷你字母键盘——并修好切应用后键盘底部偶尔被系统虚拟按键挡住、要收起再打开才恢复的问题。沿用正式签名，可覆盖升级并保留设置与词库。

## 更新内容

- **面板不再带搜索**：符号（表情、颜文字）、剪贴板与常用语面板里的搜索行，以及点开后铺出的三行字母键整套撤掉。面板本来就盖住了主键盘，里面再塞一副又窄又小的键盘不如不给这个入口：表情仍按分类与收藏找，剪贴板与常用语按卡片浏览。面板恢复成「表头 + 网格」两段，网格整屏可用。为搜索做的目录名称与拼音索引、内核读音查询接口、实体键盘的按键路由与查询状态一并移除；表情目录里的英文名与逐字拼音留着（无障碍播报在用）。Mac 表情库窗口里的搜索框没有动——那是独立窗口里的真输入框，不是面板里的迷你键盘。

- **键盘不再被系统虚拟按键挡住**：切应用的动画、窗口进出场、系统重算边衬时，导航栏高度会先报一次 0；键盘据此把底部留白收掉，之后没有事件再把它纠回来，于是一直压在虚拟按键下面，要收起再打开（或点一下键）才恢复。现在：三键导航下第一帧就按系统资源 `navigation_bar_height` 留出底边（手势导航不预留）；把某条边整个收成 0 的读数不当真，记下来隔 180 ms 复核、两次读数一致才认，期间来的其它读数（变大的、变小的但不归零的、横屏换到侧边的）照旧立刻生效——多留一条空白只是不好看，少留就把键压在系统按键下面；键盘显示后在 120 / 350 / 700 ms 再各量一次，因为切应用的动画走完、窗口真正定位好都不在显示那一瞬。复核按时间算不按次数：那一下 0 常常连着几次重读都在，按「第二份相同读数」认等于没认。

- 其余与 beta.25 相同：内核、词库与数据这一版没有变化。

## 下载与升级

- 手机：`WeaveText-0.1.0-beta.26-arm64.apk`，Android 8.0+、ARM64，沿用正式签名，可覆盖升级并保留设置与词库。包含离线语音运行库，语音识别模型按需下载。
- Mac：`WeaveText-0.1.0-beta.26-mac.dmg`，macOS 13+，Apple 芯片与 Intel 通用。打开 DMG 后按安装器提示操作；安装包未作 Developer ID 签名和公证。
- 可选 Google 离线翻译插件：`WeaveText-Google-Offline-Translation-0.1.0.apk`。
- 可选 Apple 系统翻译适配插件：`WeaveText-Apple-Offline-Translation-1.0.0.zip`，需要 macOS 15+。
- `SHA256SUMS.txt`、`SHA256SUMS-plugins.txt` 与 `SHA256SUMS-mac.txt` 分别提供对应文件的 SHA-256。

翻译插件与 Mac 应用本版没有功能变化，插件无需重新安装。

## 验证与当前边界

内核这一版只改了版本号、没有代码改动，未重跑内核全量（沿用 beta.25 的 **222** 项通过，按 CI 的 `--features weave-dict/pack` 为 **223** 项）。Android 全量 **958 项** 0 failures、`lintDebug` 0 errors（977 → 958 减少的是随功能撤掉的搜索用例）。导航相关用例改写并新增 6 项：过场中的 0 不收起留白、真的收起时复核后照样让开、第一帧就按系统资源留出底边、三键与手势导航的预留、按次数不算复核；三条先写出失败的判据再修，其中两次失败暴露的是复核逻辑本身的问题（第一份 0 被 `held == null` 分支直接生效；按次数复核等于没复核）。`HandwritingAreaModeTest` 里那条「系统栏变化」用例跟着改成「归零那一下先不当真，复核后再收掉」。

模拟器冒烟（1080 × 2400、420dpi、三键导航、底边 126）：`dumpsys window` 显示输入法窗口铺到屏幕底边 `[0,1366][1080,2400]`、导航栏压在 `[0,2274]` 之上，与「底边要自己让」的判断一致；连做 5 轮「回桌面 → 开设置 → 回来 → 点输入框」，每轮截屏检查导航栏那一条（y ≥ 2274）有没有键面白像素，5 轮全干净；面板也确认只剩网格、没有搜索行。

**没有在实体手机上验收**：模拟器复现不出用户说的那种状态（切应用后压在虚拟按键下面），改动是按根因与用例写的；`tools/device-smoke.sh` 未跑。Mac 表情库窗口的搜索框按上文保留。
