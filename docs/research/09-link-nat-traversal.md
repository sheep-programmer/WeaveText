# 互联与 NAT 穿透

局域网发现仍用 `_weavelink._tcp`，现有 TCP 通道继续工作。
`core/weave-link/src/p2p.rs` 新增主动开启的跨网直连：同一 UDP socket 做 STUN 地址探测、双向打洞和 QUIC 传输。
QUIC 提供重传、排序、流控及加密；上层继续用 SPAKE2 + Noise 配对并核对设备静态身份。
连接码绑定临时 TLS 证书、设备 ID、候选地址和配对码，5 分钟过期。两端必须互换连接码才允许配对。
没有数据中继、TURN，也没有自动信令服务器或完整 ICE 实现；失败就报告直连失败。

用户步骤：两端设置 › 互联 › 跨网直传，各生成连接码并发给对方，再各自粘贴对方连接码、点击连接。
之后复用已有发送文件、剪贴板和个人资料的流程。网络改变、程序重启或连接码过期时，重新生成并交换。
STUN 默认使用 Google / Cloudflare 的公开地址探测服务，只发送协议请求，不发送文件内容。
跨网直连不保证适用于所有 NAT；对称 NAT、UDP 封锁等场景可能失败。

## UDP 打洞的条件

1. 两端从同一 UDP socket 收集本地地址和 STUN 返回的公网映射，保持映射存活。
2. 通过信令通道或双方手动交换候选地址及会话凭据。STUN 本身不负责把对端地址交给另一台设备。
3. 使用 ICE 连通性检查选择实际可用的地址对；网络变化时重新收集、检查。
4. 在所选 UDP 路径上建立可靠、经过身份认证的加密传输；文件需要顺序、重传、流控和完整性校验。
   现有 TCP 帧读取和 Noise 顺序 nonce 不能原样用于会乱序、丢包的 UDP 数据报。
5. 如果需要覆盖无法直连的 NAT / 防火墙，提供 TURN 或其他中继作为后备。
   仅提供打洞可以保持数据直传，但必须允许清楚地报告连接失败。

信令和 STUN 可以只协助建立连接，不转发文件内容；中继则需要承载加密数据。
产品说明使用“文件不经过中转”，同时告知跨网地址探测服务的用途。

## 验证边界

- 核心回归：真实 UDP 配对、双向文字与文件内容校验；不提供 TCP 对端地址，连接事件必须报告 `direct-udp`。
- `tools/link-device-check.py --serial emulator-5554 --direct`：测试 STUN 服务仅返回 Android 模拟器 NAT 的映射；
  Mac 与手机通过独立的 QUIC socket 双向传图片、文件和个人资料，地址探测服务不转发数据。
- 上述测试不能代替两台真实设备处于不同公网 / 运营商 NAT 的实测。

## 标准依据

- [RFC 8489 · STUN](https://www.rfc-editor.org/rfc/rfc8489)：发现公网地址、检查连接、维持 NAT 映射；它本身不是完整的穿透方案。
- [RFC 8445 · ICE](https://www.rfc-editor.org/rfc/rfc8445)：候选地址收集、通过独立信令交换、STUN 连通性检查和路径选择。
- [RFC 8656 · TURN](https://www.rfc-editor.org/rfc/rfc8656)：不能直接通信时，由中继承载数据。
