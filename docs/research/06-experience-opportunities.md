# 输入法优势对比与织文下一轮体验改进

调研日期：2026-10-02。织文基线：`c519d02`（beta.12）。

本次查阅项目 README、官方使用文档及必要源码，并对照织文实现。下文的“优势”指来源中明确描述的能力；“建议”是针对织文的产品与工程判断。优先级和投入是估计，不是已完成的功能或性能承诺。

## beta.13 实施状态

本轮已实现候选固定／降权、选区重选、英文拼写建议、中英片段组句、加密个人资料发送与合并、适配模型的语音个人热词、手写纠正持久化，以及快捷码日期／时间模板。手机与 Mac 均有对应入口；手写另增加字间留空的 2–4 字模式。详见 [实际入口与边界](../personal-features.md)。

此处“个人资料”包括词库、候选偏好、近期选择、手写样本与短语，不包括全部应用设置；模板当前只自动填日期和时间。新的大型英语下一词模型、任意草书全句、按应用设置、滑行与本地文本模型仍是后续建议。以下对照表保留 beta.12 的调研基线，不应读作 beta.13 仍未实现上述八项。

## 结论

最值得先补的是：**候选的直接控制、已上屏文字重选、英文纠错与更完整的中英混输**。这些与“常用字不靠前”“英文不会联想”“改错太麻烦”的实际问题直接相关。

第二批是个人词库与偏好的跨设备同步、语音个人热词、手写字形持久学习、短语快捷码。全句手写、可选本地文本模型和英文滑行输入需要更多模型、数据及性能验证，适合后续单独推进。

## 别的输入法有哪些值得借鉴的优势

| 项目 | 已核实的优势 | 对织文的启发 |
|---|---|---|
| [Microsoft SwiftKey：多语言](https://support.microsoft.com/en-us/swiftkey-keyboard/how-to-use-microsoft-swiftkey-keyboard-with-more-than-one-language) | 同布局语言可以一起预测；不同字母布局有切换机制 | 让中英片段共同参与解码，保护英文缩写和大小写；不能把“支持多语言”直接等同于任何中英句子都可无切换输入 |
| [Microsoft SwiftKey：剪贴板快捷码](https://support.microsoft.com/en-us/swiftkey-keyboard/how-does-the-clipboard-work-with-microsoft-swiftkey-keyboard) | 保存的短语可以关联快捷码，输入快捷码后从候选中插入 | 给织文常用语增加快捷码，进一步支持日期和可填写字段；模板能力是织文的延伸建议 |
| [Apple 简体拼音](https://support.apple.com/zh-cn/guide/chinese-input-method/cimpys11836/mac) | 除拼音外，支持按字的部件读音及笔画找字 | 不知道读音、手写又认不准时，提供拆字和笔画入口，例如用两个“吉”的读音找“喆” |
| [Gboard 手写](https://support.google.com/gboard/answer/9108773?hl=en&co=GENIE.Platform%3DAndroid) | 提供按语言选择的手写面板，可用手指或笔书写；语言支持有范围限制 | 后续把字母、数字或多字手写做成明确的可选模式，保留织文不自动添加英文空格的要求 |
| [Apple 触控板手写](https://support.apple.com/zh-cn/guide/chinese-input-method/scim27935/mac) | 可书写多个字符，支持草体，并根据选择改善候选 | 手机可做全屏多字连写；Mac 可从系统输入法菜单打开书写窗口。借鉴交互，不代表可以调用或复制苹果识别引擎 |
| [Mozc 重新转换源码](https://github.com/google/mozc/blob/master/src/session/session.cc) | `ConvertReverse` 读取已有文本的读音并重新显示转换候选 | 用户选中已输入词后重新选词，替换原选区，省去删除和重打 |
| [青简：本地整句模型](https://qingjian.app/docs/input/local-model) | 在输入停顿后用本机模型改善整句；翻页或移动高亮后避免改变当前候选 | 词库即时出结果、模型在后台补强；优先保护正在点选的候选和个人习惯 |
| [青简：辅码](https://qingjian.app/docs/input/aux-code) | 拼音后追加少量形码／笔画码筛选同音候选 | 对候选很多的单字提供快速收窄入口，减少翻页 |
| [青简：英文模式](https://qingjian.app/docs/input/english-mode) | 英文补全、纠错，支持按应用关闭，避免与终端和编辑器补全冲突 | 让语言与候选行为可以按应用记住；保留原文上屏和用户自己的空格习惯 |
| [HeliBoard](https://github.com/HeliBorg/HeliBoard) | 多语言、可定制布局及设置／学习数据备份恢复 | 跨设备迁移应包括个人词和偏好，而不只传剪贴板；布局入口可继续简化 |
| [AnySoftKeyboard](https://github.com/AnySoftKeyboard/AnySoftKeyboard) | 支持词建议、下一词建议、可配置纠错、滑行和无痕模式 | 英文需要完整的词级纠错与接续；补一个用户可主动切换的无痕入口 |
| [Fcitx5 Android](https://github.com/fcitx5-android/fcitx5-android) | 英文拼写检查和多种输入引擎，词表／Rime 插件扩展 | 英文“补全”和“拼写纠错”应分别建设；把找字入口和词库扩展做得容易发现 |
| [FlorisBoard](https://github.com/florisboard/florisboard) | 剪贴板、主题和扩展体系；README 同时注明当前发布版的单词建议／拼写检查尚未提供 | 适合借鉴工具组织及扩展交互，不据其路线图声称已有成熟预测能力 |

Rime 系列的价值是输入方案与词典可配置，可参考 [Rime 配置指南](https://github.com/rime/home/wiki/CustomizationGuide)、[同文](https://github.com/osfans/trime)与[仓](https://github.com/imfuxiao/Hamster)。这不意味着织文必须要求普通用户编辑配置文件：常用操作应直接放到界面上。

## 对照 beta.12，具体还能加什么

| 优先级 | 建议 | 当前基础／缺口 | 用户实际得到什么 | 投入判断 |
|---|---|---|---|---|
| P0 | 候选“固定第一／取消固定／降低优先级” | 已有近期偏好学习；候选长按主要支持删除用户词 | 常用字一次设置即可优先，不必反复选；固定和自动学习分开管理 | 较小至中等 |
| P0 | 选中文字后重新选词 | 有编辑和光标操作，尚无重新转换流程 | 已输入的同音错字可直接换掉，保留周围文本 | 中等，依赖应用的选区支持 |
| P0 | 英文拼写纠错与更丰富的下一词建议 | 已有前缀补全、个人词和少量接续；暂无完整英文错拼搜索 | `recieve` 能提示 `receive`，短句中下一词更有用；原文仍可选择 | 中等，需词表与评测 |
| P0 | 完整中英片段混输 | 当前是拼音整句与部分英文词插入，未形成通用混合片段解码 | “今天 review 这个 PR”这类输入减少切换；缩写、数字和英文大小写不被破坏 | 中等至较大 |
| P1 | 个人词、偏好及设置的加密同步 | 互联已能传文件和剪贴板，未专门合并学习记录 | 手机学会的人名／术语在 Mac 上也能优先，换机不重新训练 | 中等，需要去重及删除冲突处理 |
| P1 | 语音个人词汇 | 已有多模型；尚未把个人词表接入识别 | 人名、地名和行业术语更容易成为识别结果 | 按模型实施，不能一概而论 |
| P1 | 手写字形持久学习 | 已有纠正样本，但只在当前引擎进程保存 | 重启后仍记住用户容易写混的字形，可查看、删除与清空 | 中等，需持久化及形近字验证 |
| P1 | 常用语快捷码与模板 | 已有常用语卡片，尚无快捷码展开和模板字段 | `dz` 出常用地址；日报模板填日期、项目名后再插入 | 较小至中等 |
| P1 | 按应用记住输入行为 | 有按输入框类型处理；暂无完整应用配置 | 聊天与写代码分别记住语言、标点和候选行为，可手动覆盖 | 中等 |
| P1 | 拆字、笔画、可选辅码 | 有手写及五笔反查，缺少这些快捷找字入口 | 不会读的字也有第二、第三种输入办法，同音字不必翻很多页 | 中等，需合适的数据 |
| P1 | 习惯性错拼与误触校准 | 已有邻键和常见错拼纠正，尚无个人误触偏移模型 | 根据明确接受的改选逐渐改善自己的常见错误 | 中等；需防止把合法输入学成错误 |
| P2 | 全屏多字连写 | 当前手写识别单位为单字 | 连写短词或两三个字后一起选词 | 较大，需分字及多字评测 |
| P2 | 可选本地整句模型 | 当前使用词库、搭配模型和学习，没有新的神经文本重排流程 | 少见的口语长句候选更自然 | 较大，先测准确率、延迟、耗电和内存 |
| P2 | 英文滑行输入 | 已有滑动光标／删除等手势，尚无轨迹到单词解码 | 单手不抬指输入英文词 | 较大，需轨迹数据及独立识别器 |
| P2 | 候选译词／生词本 | 尚无双语释义界面；青简已有候选旁译词与本地词汇记录 | 忘记英文表达时提供辅助解释 | 中等，默认可关闭，不挤占中文候选 |

英文滑行不是“已经有几个滑动手势就能顺便做”：还需要轨迹解码和语言模型。HeliBoard 的 README 明确说明其滑行依赖外部闭源库；不能以此断言可以直接拿到完整开源实现。AnySoftKeyboard 可作为另一条实现参考。

## 语音热词的实际边界

[sherpa-onnx 热词官方文档](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)说明，其这套上下文偏置面向 transducer 模型，并需使用 `modified_beam_search`。当前织文的 transducer 路径已经有 beam 配置，beta.13 已接入适配的个人热词（详见上述实施状态）。

建议先向支持的模型提供用户确认的人名、地名、术语，并显示“此模型支持热词”。CTC、SenseVoice、Paraformer、Whisper 等不能沿用同一接口假装都支持；可分别评估自身上下文参数或结果纠正。结果纠正只作为可选建议，保留原识别，避免把相似发音一律替换为个人词。

## 建议的实施顺序及验收

1. **候选控制 + 重选改错**：给常用字明确控制权；已输入文字替换时只修改选区。验证取消固定、立即撤销、应用拒绝选区、重启与隐私输入框。
2. **英文纠错 + 混输**：保留原文候选、缩写和大小写；点选英文不自动加空格。用中英片段、人名、代码名、错拼和标点句做评测。
3. **词库同步 + 语音热词**：只向已配对设备同步，用户可选同步内容；重复传输不重复增加次数；删除记录能传播；逐模型核实热词效果。
4. **手写与短语效率**：先保存个人字形、快捷码，再做多字连写；错选后的删除能撤销本次学习。
5. **模型与滑行**：后台运行，并冻结用户正在浏览或点选的候选。没有基准对比就不承诺更准或更快。

## 织文已经有，不应作为新功能重复安排

全拼／双拼／九键、模糊音与部分错拼纠正、近期学习和撤销、英文前缀补全、空格横滑光标、删除清空后的撤销、单手／悬浮／分离键盘、媒体剪贴板和常用语、专业词库、多离线语音结果、真实音量波纹、语音模型缓存、配对文件传输均已有基础。

相关核对入口：`core/weave-engine/src/{session,userdict,graph}.rs`、`core/weave-dict/src/handnet.rs`、`core/weave-ffi/src/asr.rs`、`android/.../ime/InputController.kt`、`android/.../ui/keyboard/{WeaveKeyboard,ClipboardPanel}.kt`、两端 `LinkService/LinkManager`。

继续保持用户已明确的体验要求：英文候选不默认加空格；Mac 的功能进入系统输入法菜单；离线语音先下载模型；个人输入资料不因新功能而默认上传。
