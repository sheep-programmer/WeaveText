# 手机手写与悬浮键盘优化

2026-10-06。本轮四个 agent 并行完成开源体验调研、识别器与分组修复、悬浮几何和设置、笔迹渲染；主线程接线并验证。

## 手写怎么用

- 手写键盘右侧的「单字／连续连写」键切换模式，保留已写笔画并重新识别。
- 单字可以按停笔间隔连续输入；连续连写是“写完一个字，再写下一个”：下一次落笔确认前一个字，前一个字的墨迹慢慢淡出，避免两个字的笔画混在一起。
- 「输入方案 → 手写 → 停笔自动上屏」可以关闭。关闭后不因停顿清掉笔迹，点候选、空格或回车才确认，适合慢写和仔细选字。
- 删除键撤销一笔；长按「单字／连续连写」键重做上一笔；「重写」清空当前字。新笔画结束后清除旧重做历史。
- 首选不对时，可以展开或滚动候选选择；单字候选上限由 12 扩到 30，选词与原有字形适应继续使用。
- 「输入方案 → 手写笔迹」选择圆珠笔、毛笔、铅笔、荧光笔，调整 2–12dp 粗细；颜色支持跟随主题、预设色与自定义 `#RRGGBB`。
- 触控笔压力只影响墨迹显示。笔锋尖尾、平滑、粗细与颜色不改变交给识别器的原始接受坐标；切换外观会重绘现有墨迹。

后台识别会显示「识别中」。新笔画取代旧的未确认识别，停笔确认按书写顺序完成；清空、新输入框或外部光标移动会丢弃过期结果，避免迟到文字插入错误位置。
关闭自动上屏会取消已排队的停笔回调。同步识别已有结果但没有候选时，保留笔迹并提示继续书写或重写。

## 悬浮键盘

默认不限制缩放位置，四角都可拖动。在「外观与手感 → 悬浮键盘缩放」中可选择任意非空角集合，也可以四角全选。
有空间时固定对角；靠屏幕边缘时平移避让，让贴底的下方两角也能放大。尺寸仍受窗口范围限制，横竖屏的大小和位置分别保存。

四个控制区放在按键及候选栏之外。通常上下控制条各 48dp；极短窗口使用紧凑控制条并按可用空间调整尺寸，避免控制区把按键挤出屏幕。
右上区域采用独立 X 按钮，关闭悬浮模式并停靠到底部；中间拖动条仍用于移动卡片。取消缩放手势恢复原尺寸，不保存半截拖动。

## 识别改动与验证范围

修复模板剪枝遗漏相邻连笔／断笔匹配的情况；近距连写先按空间分组，再还原各字原笔顺；整字强模板保护降低偏旁被误拆的风险。
组句保留每字实际提供的第五候选；四字最多 625 个组合，较长的兼容传输使用有界 beam，未增加任意长度或多行书写入口。

强模板检查采用固定门槛、找到匹配即提前结束；复用合笔特征，以有界缓存保存不可变模型分数。个人纠正与上下文每次仍重新应用。
本轮没有替换模型权重、训练研究专用笔迹数据，或把第三方闭源模型并入默认识别器。

公开字形的合成扰动与拼接测试证明了上述具体修复，**不能当作真人准确率**。单字融合首选准确率在该测试中没有提高，重度草书、跨字一笔连接、叠写、多行及任意长句仍未完整支持。
开源项目的体验对照、已实现／缺失功能和后续建议见 [调研记录](research/11-mobile-input-experience-and-handwriting.md)。

本轮验证包括 Rust 手写／传输／候选容量回归，Android 真实触摸回放、异步完成与取消、笔迹渲染和设置即时更新，以及两端安装包检查。
最终结果：Rust 手写单测 19 项、候选容量和上下文集成 6 项通过；Android 最近一轮定向 JVM 回归 117 项通过；独立 Android 31 arm64 模拟器上，5 项悬浮触摸测试及 1 项真实 JNI 手写流程通过。
模拟器验证了四角缩放、指定角集合、取消恢复、X 停靠、贴底右下角放大，以及使用包内识别器书写「十」、笔迹设置保留坐标、撤销/重做、连写「十十」并上屏。真实触控笔硬件尚未验证。
Mac 189 项测试通过，通用二进制包含 arm64/x86_64。APK 签名、语音 JNI、Mac 签名及 DMG 校验通过；Debug/Release APK 的 `libweave.so` SHA-256 相同。
桌面合成评测耗时不代表手机性能；本轮没有确认通用真人单字准确率的提升。

最终性能抽查：同一组 80 个公开字形合成 level 4 样本，原版／最终版平均融合识别耗时为 44.84／30.79ms，p95 为 75.44／39.55ms；融合首选 27.50%、前五 52.50% 均未改变。
模板首选由 58.75% 到 61.25%，请求一候选与请求完整列表的首选不一致由 3 次到 0 次。这只是单次、单机、同组抽查，不是手机持续性能或真人准确率。
同组近距几何拼接的正确分组及笔顺，两字由 0% 到 97.50%，四字由 0% 到 95.00%；此指标评价切分，不是整行文字识别率。
