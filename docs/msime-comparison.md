# 水杉输入法（MSIME）与 WeaveText：证据、差距与独立实现建议

调研日期：2026-10-10。WeaveText 基线：工作区 `/Users/sheep/Public/git/WeaveText`，HEAD `2878db5b288fe9dd5f62d670a7b35c531b2ab978`，Android 构建配置为 `0.1.0-beta.21`。工作区包含尚未提交的应用、扩展市场和文档改动；以下“已有”指阅读时的工作区实现，不保证已经进入公开安装包。

后续用户已明确要求查看官方仓库源码。本文前半部分保留上一轮官网／文档调研的取证快照；源码阶段的固定提交、平台差异、语音实现与参考项目见 [官方源码复核](msime-source-review.md)。新增实现仍独立编写，不引入竞品源码、词库或模型。

## 1. 决策结论

应学习水杉把候选、消歧、语言切换和扩展入口放在实际输入流程中的做法，但优先改善织文已有能力的可靠性。建议首先处理：

1. **下载失败后能继续完成任务**：已有镜像、续传和校验，不必重做下载器；补齐失败分类、明确的下一步、跨重启恢复及 Mac 下载能力差异。
2. **中英混输可控且两端一致**：已有英文候选和全拼中的英文片段解码；真正机会是双拼内嵌英文、技术词与数字符号、原样保留，以及宿主按键行为与内核能力之间的衔接。
3. **候选消歧减少选字成本**：已有学习、注音和展开；优先增加以词取字、组合串局部修改、实体键盘导航，再考虑可选辅助码数据包。
4. **长候选、慢识别与无障碍始终可操作**：将潜在同步等待、候选全文可达性和真实读屏验证纳入基础质量门槛。
5. **隐私说明与真实数据流一致**：保持基本打字离线，完整说明翻译、联网语音插件、下载镜像与互联的独立边界。

不建议把多语言方案、云账号、AI 回复、每候选在线翻译、音乐或打字特效全部塞进默认输入路径。它们是否值得做，应由具体用户任务、离线收益和维护成本决定。**没有同设备实测，因此本文不判断水杉比织文更快、更准，或哪一个手写识别率更高。**

## 2. 调研方式与证据等级

### 2.1 范围与独立实现边界

- 竞品证据来自 web 工具读取的官网、使用指南、隐私说明、GitHub Release 正文和版本锁定的公开 README 功能说明。未克隆竞品仓库，未打开竞品实现源码、提交 diff、模型权重或插件代码，也未下载竞品安装包。
- Android 与 macOS README 仅作为公开平台说明，不能把里面维护者描述的测试当成本次执行的测试。文中的改进方案从织文自己的接口、数据结构和用户任务推导，不能移植竞品实现、码表、词库、皮肤或测试数据。
- 父任务负责用 ego-browser 视觉复核。本次没有创建浏览器 TaskSpace，没有操作账号、安装输入源或向外部服务提交输入。本报告不提供未经观察的视觉体验评分。
- 父任务补充：`/docs/android/` 为 404；本次 web 打开也未得到可读正文。Android 不引用这个地址作为指南。`/docs/` 和 `/docs/windows/` 实际是 Windows 指南，其导航可找到 macOS 与 macOS 语音指南。[Windows 指南][s04]
- 父任务正在创建新的公开市场 `sheep-programmer/weavetext-market`。该方向与原有私有资源仓库分开；本次没有打开私有仓库，也没有核验新公共仓库是否已发布内容或客户端是否已经接通它。本文不把父任务进行中的创建工作算成已交付能力。
- 本任务仅新增此文档，不改应用、配置、既有文档或测试。

| 标记 | 证据含义 | 能支持的结论 | 不能支持的结论 |

本次 E 类应用实测为零。web 能读到页面正文是网页取证，不是输入法运行测量。下文验收用例和时间预算均为**建议目标**，不是当前通过结果或竞品性能数据。

1. 下载页 Android 安装段已有测试包入口，但同页发布汇总仍残留“Android 尚未发布”。采用具体 Android Release 和安装段，不采用旧汇总文字。[下载页][s02]、[Android 0.3.1][s09]

这些冲突也是织文发布信息的改进机会：官网、安装包、市场目录和隐私说明应有明确版本与平台对应关系，不让用户自行判断哪段说明过期。

## 5. 织文实际能力与缺口定位

### 5.1 输入、候选、纠错与英文

| 维度 | Android 当前实现 | macOS 当前实现 | 真正的差距或待验证点 |
| --- | --- | --- | --- |
| 打字与整句 | 共用 Rust 全拼、简拼、模糊音、双拼、九键/14 键；宿主有未就绪按键队列 | 同一 Rust 内核，实体按键映射与候选分页 | 已有整句，不能写成“缺少智能组句”。没有同集证据证明 F01 的多方案比我们的常用方案更准。[内核](../core/weave-engine/src/session.rs)、[手机输入链](../android/app/src/main/java/com/weavetext/ime/ime/InputController.kt) |
| 候选选择与学习 | 横向候选、展开、降权/删除学习；候选改变时取消正在按住的旧候选 | 横/竖、展开、分页、自定义候选按键；动态学习 | 已有最近明确选词、跨方案学习及撤销。不要新增永久固定默认规则抵消动态偏好。[学习说明](learning-and-english.md)、[手机候选栏](../android/app/src/main/java/com/weavetext/ime/ui/keyboard/TopBarView.kt)、[Mac 候选](../macos/Sources/WeaveText/CandidatePanel.swift) |
| 组合串编辑 | 退格主要从末尾删；候选栏预编辑行不提供插入点编辑；文档光标工具另有实现 | 中文方向键主要移动候选高亮 | `raw`、`consumed`、`selected` 模型未暴露组合插入点、按音节移动/删除操作。**文档光标移动、重转换不等于组合串中途修改**。[Session](../core/weave-engine/src/session.rs)、[特性接口](../core/weave-engine/src/session/features.rs)、[Mac 按键](../macos/Sources/WeaveCore/KeyMapping.swift) |
| 消歧与注音 | 可选注音只标首选；展开仅文字；九键可锁拼音 | 可选注音只标高亮项 | 已有注音但没有通用以词取首/尾字与辅助码过滤接口。拼音注音通常不能区分同音字的字形含义，应提供更直接的取字或筛选方式。[候选注音说明](learning-and-english.md)、[特性接口](../core/weave-engine/src/session/features.rs) |
| 中文纠错 | 已有颠倒、漏字、多字、邻键及触点候选；用惩罚和原读法保护歧义 | 共用纠错与开关 | `typo_variants` 保护合法音节，Session 还保留字面候选；应测误纠率与回退成本，不能因竞品广告再造一个纠错器。[音节图](../core/weave-engine/src/graph.rs)、[评测说明](../data/eval/README.md) |
| 独立英文 | 补全、个人词、大小写、撤销；点候选不自动加空格，主动空格才写入 | 默认英文直通，补全与联想分别可开启 | 原样优先是现有意图，应保留；候选纠正不等于自动改字。系统性口语、技术词与误纠评测仍不足。[英文实现](../core/weave-engine/src/session.rs)、[学习与英文](learning-and-english.md) |
| 中文内英文 | 全拼 `refresh_pinyin` 调用 `decode_with_latin`；`mix_english` 还能给整串英文候选 | 同一内核，宿主对大小写、数字与快捷键另有处理 | **不是“没有句中英文”**。片段解码目前仅全拼接入；双拼主要依靠整串英文候选注入。数字、连接符、技术词及宿主的大写直写路径需要共同验收。[Decoder](../core/weave-engine/src/decoder.rs)、[Session](../core/weave-engine/src/session.rs)、[混输测试](../core/weave-engine/tests/mixed_english.rs) |
| 重转换与编辑 | 已有选中文字重新候选与目标检查；文档光标按字形簇移动 | 已有选区重转换与客户端归属检查 | 保留已有能力，补组字中的编辑，不以重复实现重转换冒充差异化。[手机控制器](../android/app/src/main/java/com/weavetext/ime/ime/InputController.kt)、[Mac 控制器](../macos/Sources/WeaveText/InputController.swift) |

英文现状有一个容易误读的细节：`refresh_english` 先保留原文，优先查前缀，未找到补全时才运行词表纠正；`table::corrections` 使用有界编辑距离候选。原文首项和手动选择保护了“不要擅自纠正”的规则，但也可能让某些错拼只出现不合意的前缀补全。这是应拿输入样本测量的召回/排序机会，不是已经证实的普遍失败。[英文查找](../core/weave-engine/src/session.rs)、[词表纠正](../core/weave-engine/src/table.rs)

## 6. 优先级与核心/插件边界

P0：发布前应核查的基本可用性、可恢复性及数据边界；发现实际缺陷再修复。P1：高频任务的直接改善。P2：有明确需求再投入的扩展。优先级不是依据竞品是否广告过某项功能。

“必须保留核心”指无市场、无账号、无可执行插件时仍可用的输入保障。“可选插件”含数据包、独立平台适配器或内置可关闭模块，不代表所有东西都应在 Lua 内实现。

| ID | 优先级 | 具体交付 | 边界 | 为什么现在做 |
| --- | --- | --- | --- | --- |
| A01 | P0 | 下载失败分类、可恢复动作、跨重启继续与已安装资源保护 | 下载/校验/取消核心；资源内容可选 | 首次使用语音或词库的实际完成率，已有 fallback 的收益应让用户看得见 |

## 7. 可实施方案与验收用例

### A01 · 下载 fallback 从“后台会尝试”变成“用户能恢复”

**定位**：Android `Downloader` 已负责坏镜像、续传、校验；`ModelFetcher` 负责逐文件/压缩包路线；UI 有源选择、取消与重试。`ModelManager` 已预估空间、故障时保留 staging/分片，`VoicePack.friendly` 区分校验错误与一般网络错误；现有主动取消会清理分片，解包阶段则不提供中途取消。Mac 也已有进度和重试。应细化任务状态和恢复动作，不重复实现这些已有能力。[Android 下载器](../android/app/src/main/java/com/weavetext/ime/models/Downloader.kt)、[模型管理](../android/app/src/main/java/com/weavetext/ime/models/ModelManager.kt)、[友好错误](../android/app/src/main/java/com/weavetext/ime/models/VoicePack.kt)、[Mac 下载界面](../macos/Sources/WeaveText/Settings/DictionaryPages.swift)

**独立实现**：每次下载保存资源 ID/版本、可信大小/摘要、阶段、已完成文件和当前来源；区分连接失败、源文件不存在、校验失败、空间不足、取消。面向用户显示“正在换下载源”“已保留下载进度”“文件校验未通过”及可用动作；完整技术原因仅放在可展开的脱敏详情。新增“暂停并保留”与“取消并清理”的明确区别，重试不删除已经验证的文件。解包不能抢占取消时，说明正在完成当前步骤并禁止最终启用被取消的模块。官方公开资源不要求 GitHub 登录；私有第三方插件则保留独立授权。

**验收**：

- 第一源超时、第二源成功：无需重新点下载；显示换源，最终只有通过摘要的包成为可用状态。
- 第一源返回 404、另一条路线成功：说明备用来源正在工作，不显示“换账号才能下载”等不相关动作。
- 已下载 40% 时暂停/进程退出：下次给“继续下载”；在来源支持 Range 时保留进度。不支持或资源版本变更时明确重新开始，禁止拼接不同资源。“取消并清理”则明确告知释放未完成下载，下次重新下载。
- 两个源全部失败：普通用户看到原因类别及“重试/切换来源/稍后再试”；公共资源还可提供官方发布页和受校验约束的本地导入。
- 空间不足：保留已有空间预估，并显示所需下载及解包空间和可操作的管理入口；已有模型和用户词不被自动删除。校验错误丢弃坏分片，保留其他已校验文件。
- 失败期间仍能普通拼音打字；扩展停用后取消任务和迟到安装回调，保持已安装资源状态一致。

**成功指标**：受控故障场景完成率、重试后的重复下载字节、取消响应、用户恢复步骤数；不以广告中的“极速下载”作指标。竞品 F09/F10 启发恢复出口，未测其 fallback 速度。

### A02 · 手写任务的所有交互都不等后台推理

**定位**：保留已有代次、排队上屏和异步完成测试；针对 `engine → settleHand → finishHand` 的读取、退格、编辑及异常分支补验证。当前 `get(2 秒)` 是代码等待上限，随后同步 `handInput` 仍可能增加耗时，不是已经测出的用户停顿。[控制器](../android/app/src/main/java/com/weavetext/ime/ime/InputController.kt)、[异步测试](../android/app/src/test/java/com/weavetext/ime/ime/HandRecognitionAsyncTest.kt)

**独立实现**：识别和回退都留在工作队列；主线程只持有最近完成的不可变结果。待结果时明确允许、禁用或排队用户动作，不用 getter 隐式等待。以输入框代次、笔迹修订号和请求 ID 检查结果；切换输入框、外部光标变更和关闭模块后丢弃过期写回。

**验收**：注入停住 3 秒的识别器，连续撤笔、开工具、切方案、移动光标、收起键盘均不在主线程等待 Future；取消识别后不从 UI 同步再推理。恢复后只允许当前目标、当前笔迹结果出现；排队确认的多字按原书写顺序上屏。同组快速笔迹没有丢笔，已有清空/停笔/新笔画回归继续通过。

### A03 · 隐私说明按触发条件完整列出

**定位**：手机 Google 网页入口把文本放进 URL 参数；Mac 同类功能、语音插件和更多工具也已接线。两端 About 隐私列表不完整。竞品 F11 的价值是可读的出口清单，默认统计或匿名账号不是织文需要模仿的功能。[手机翻译](../android/app/src/main/java/com/weavetext/ime/translate/TranslationWeb.kt)、[手机隐私](../android/app/src/main/java/com/weavetext/ime/settings/AboutScreens.kt)、[Mac 隐私](../macos/Sources/WeaveText/Settings/AboutPage.swift)

**独立实现**：列基本输入、网页翻译、自定义翻译、离线翻译语言包、联网语音插件、模型/词库/市场下载、GitHub 授权和互联；每项包含触发、目标域或接收者、数据类别、关闭与清理。说明网页翻译的选中文字会交给 Google 网页，并可能进入浏览器历史；“离线翻译”与首次模型下载分开。维持敏感字段在宿主统一禁用学习和外送，不依赖插件自觉遵守。

**验收**：全新安装仅普通打字不发输入文本请求；打开设置或停用模块不开始翻译/录音。用户主动网页翻译时，文案准确描述文本交给网页服务。密码、无痕/禁止学习字段不给外送动作；关闭录音/模块后不接受迟到文本。导出个人资料不带 GitHub PAT、语音密钥或浏览器翻译 URL。对完整数据流做受控网络观察，不能从静态开关推定“绝对无联网”。

### A04 · 验证覆盖必须可判断

**定位**：1000 句评测、50 个纠错用例、混输/适应学习和内核耗时测试已经存在；部分真实词库测试在构建数据缺失时直接返回。不是“没有评测”，而是发布需证明哪些数据确实参与了测试。[评测说明](../data/eval/README.md)、[混输测试](../core/weave-engine/tests/mixed_english.rs)、[耗时测试](../core/weave-engine/tests/typing_latency.rs)

**独立实现**：发布验证固定词库/模型摘要，记录实际执行的用例数、跳过原因及平台；新增盲留出的聊天、姓名、技术词、混输与用户纠正任务。以“选词次数/返回原文/误改率”补充 Top-1，避免只优化内部整句集。

**验收**：资源缺失时发布验收明确失败或标记不可用，不能把零次真实词库用例报成全通过；清洁用户目录和已有学习目录分别测试。给出每个输入的目标、实际候选、是否误改和恢复动作；测试数据不取自竞品词库或候选结果。性能协议见第 8 节。

### A05 · 中英混输：先保护意图，再提高召回

**定位**：全拼已有英文片段解码，双拼有英文整串候选；现有真实词库测试覆盖 `school`、`wifi`、`dont` 和 `women → 我们` 等。宿主中文大写直写、数字/标点收尾也会影响用户最终看到的行为。[混输测试](../core/weave-engine/tests/mixed_english.rs)、[片段 Decoder](../core/weave-engine/src/decoder.rs)、[手机硬件按键](../android/app/src/main/java/com/weavetext/ime/ime/HardwareKeys.kt)

**独立实现**：维护不可丢失的原始输入与中文/拉丁片段映射；将显式大小写、用户选过的词及手动“按英文保留”的片段视为意图，不把所有不合法拼音猜成英文。为双拼设计有界英文片段路径，保留双拼映射；技术词数据包提供专名及大小写，基础规则无需安装包。给临时英文保留/返回中文清晰入口，模式指示只在变化时出现。

**验收**：

- 普通 `women` 仍以“我们”为优先中文解释；需要英文 women 时可明确选择，不被中文词频永远压住。
- 全拼连续输入含 `GitHub`、`WiFi`、`API` 的中文句子：目标候选可达；回车/保留原码输出实际输入，不能丢大小写或改成无关拼音。
- 小鹤双拼输入中文片段，临时保留 `GitHub` 再继续双拼：不切到错误双拼表、不改英文大小写，中文组合不丢失。连续片段解码的实现再用独立 fixture 验证，不声称当前已经支持。
- `foo_bar`、`GPT4o`、`v1.2.3`、邮箱与 URL：字母、数字、标点能原样输入；这些字段不触发中文自动组词或额外空格。
- `don't`、`e-mail`、未知专名：有建议但原文始终可选。点英文候选仍只提交单词；主动空格才写空格。
- Mac 默认英文直通保持 `recieve`，只有主动启用补全后才展示纠正建议；Android 普通文本、密码、URI/邮箱、终端分别验证。

**指标**：中英任务所需手动切换数、正确词在前四/前八命中、原码保真、误纠率；全拼、双拼、九键分开。不要把 F05 的候选展示当成英文语言模型质量证明。

### A06 · 以词取字与可解释的候选动作

**定位**：织文候选可选、可降权，已有注音；没有“只取这个词中的某个字”的通用动作。借鉴 F03 的任务便利性，独立设计手机长按动作与 Mac 菜单/可配置快捷键。

**独立实现**：先支持取首/尾字，明确显示将插入的字；内部动作携带候选文本、候选快照与目标代次。选字不把整词拼音错误学习成单字码。以后是否支持中间字由任务数据决定。

**验收**：输入“璀璨”，选择“取尾字：璨”，只插入“璨”；正常点候选仍插入整个词。单字候选不显示无意义重复动作。候选刷新、切输入框或选区变化时旧菜单不写回；取消动作不上屏、不学习。关闭取字提示不改变普通候选排序。与翻页快捷键冲突时清楚说明，并保持应用快捷键可用。

### A07 · 组合串局部编辑

**独立实现**：为 Session 增加原始输入插入点、拼音显示位置映射、选定片段边界；移动、插入、前向删除和按音节删除是明确命令。Android 点预编辑行/专用移动动作、Mac 可配置编辑键映射同一内核操作；候选导航与组合编辑分别表达。不能仅让宿主移动文档光标来伪装组合编辑。

**验收**：`nihaoshijie` 在中间插入点删除/补回一个字母，后续 `shijie` 保留，编辑期间不提前上屏正文；选定“你好”后修改未确认部分不重复插入“你好”。隔音符、纠错标记、双拼两键单位、九键锁定音节保持位置映射一致。Esc、Enter 原码、一次退格撤销部分选词都有明确规则。外部选区变化取消过期组合写回；不能借此新增“必须全程读正文”的前提。

### A08 · Android 实体键盘候选导航

**定位**：目前方向/Tab 会先 `commitRaw`，所以“能打中文”与“能不离开组合地浏览候选”存在区别。[HardwareKeys](../android/app/src/main/java/com/weavetext/ime/ime/HardwareKeys.kt)

**独立实现**：共享候选分页/高亮操作；组字时为上下键或可配置键提供高亮，PageUp/Down 翻页，空格确认高亮。左右键待 A07 承接组合编辑。保留现有行为的兼容选项，组合外按键交回编辑器。

**验收**：连接蓝牙键盘输入 `shi`，移动到后续候选并确认，正文不先出现 `shi`；进入第二页后数字映射对应当前页。拔出键盘、打开工具再返回、系统要求同时显示软键盘时不清空候选。Ctrl/Alt/Meta 应用快捷键、终端、数字/密码框不被抢走。v 计算器里的数字继续是算式，不当选词键。

### A09 · 候选全文与无障碍闭环

**独立实现**：Mac 候选项提供明确可访问的“选择”动作、词文本、编号及可选注释；全文预览或竖排换行必须可用键盘/读屏进入。手机沿用已有虚拟节点，不因添加消歧注释重排焦点。候选身份按代次校验；纯注释刷新不改变候选顺序和按键编号。

**验收**：20 字词、长英文专名、最大字号、320dp 手机、窄 Mac 窗口与负坐标副屏中，完整内容有可达入口；屏幕边缘没有不可点击的确认区。TalkBack/VoiceOver 完成“输入、浏览第二页、听清全文、选词、取消”；无需依靠看见颜色。候选更新后焦点有确定恢复位置，手指按住候选时变化仍沿用现有取消保护。注音只读当前项、释义可选择展开，避免每键播报整张列表。

### A10 · 纠错与英文建议的保守优化

**独立实现**：在既有代价模型上增加分桶报告，不因一个广告示例扩大合法拼音的改写。英文前缀结果不合意时可以提供独立纠正候选，但原文仍首项；是否加入更多候选由误纠数据决定。

**验收**：颠倒 `sahng`、漏字、重复键与邻键分别报告 Top-3；合法歧义 `xi'an`/`xian`、语气尾词及 `women` 不被强制改写；关闭纠错立即刷新但原输入保留。`recieve` 的建议可见性与是否自动改字分别断言。用户改选后下次偏好更新，立即退格恢复此前偏好。训练与盲测数据分开，不能只报告增加召回的样本。

### A11 · Mac 下载与 Android 恢复语义对齐

**独立实现**：将较大的可选资源下载到 staging 文件，持久化分片与验证元数据，验证后原子替换。给每源独立和总任务期限；是否需要探测最快镜像由测量决定，先消除大文件全量 `Data` 与重启丢进度。继续复用两端可信资源目录，保留现有源标签、进度、取消和重试。

**验收**：弱网断连后续传、源忽略 Range、错误大小/摘要、磁盘满、取消及程序重启均不会把残包标为已安装。旧可用词库继续参与候选。镜像每次失败原因可展开，用户可主动选择来源；切源不改变校验摘要。系统离线语音资源缺失时说明去哪里准备，不冒充已下载 Android 语音模型。

### A12 · 手写质量通过真人任务决定

**独立实现**：先建取得授权的真人笔迹集，覆盖慢写、草写、部件相近字、常用单字、连续写字及触控笔压力；模型数据与用户纠正数据分开。抽象 `RecognitionRequest/Result`，允许独立平台适配器和按需模型，安全目标校验留在宿主。Google 官方说明 ML Kit 模型可按需下载并设备端识别；这只支持可行性，不证明效果更好。[Google Digital Ink][s16]

**验收**：给出字集、人数、书写设备、首选/前五、耗时分布和失败样本；“下一次落笔确认前一个字”与整行识别分别统计。关闭停笔上屏后长停顿不清笔迹；模型未装/下载失败/停用时拼音仍可用。若添加 SDK 后端，安装独立可选适配器并明确准备资源，默认自有识别器继续离线工作；未知结果、过期请求不写入编辑器。重度草书/叠写/多行只有达到独立验收才对外宣称支持。

### A13 · 布局、导航与安装的连续场景

**独立实现**：扩充既有 insets、悬浮触摸、安装与输入源检查；采用设备矩阵验证连续任务，不重复造导航避让策略。不强制统一竞品与织文的横屏/平板分体默认值。

**验收**：三键/手势导航下切拼音→手写→候选展开→浮动→旋转→停靠，删除/回车/停靠/缩放角都能操作；透明区域点击回到应用，导航键不触发输入。折叠、自由窗口缩放和外接显示器改变时组合与面板状态有明确保留规则。Mac 全新安装与旧包升级分别验证：复制完成、输入源已注册、等待重新登录、待手动添加是不同状态；错误提示有具体下一步，不假装应用能替用户授权系统操作。

### A14 · 辅助码先做一个可选试点

**独立实现**：为已完成音节提供有界形码筛选/重排接口，追加码与原始拼音明确分界；只安装一个来源清楚、许可合适、独立整理的码表包。开关、提示、退出辅助码模式属于宿主；码表属于扩展。不能复制水杉的六套码表，也不为每套写独立 Lua 输入回调。

**验收**：同一组 `shi` 等高歧义码，报告找到目标的翻页次数和附加按键数；补辅助码后目标靠前/可筛选，退格返回完整候选，普通拼音及英文技术词不被形码吞掉。未装码表时核心打字完全可用。过滤为空时显示退出/继续拼音，不静默丢输入。个人学习仍按真实读音/词条归属，不把附加码污染基础词频。只有试点确实减少操作成本才继续扩方案。

### A15 · 候选本地释义作为可选补充

**独立实现**：先在当前候选的展开信息里做本地词典查询；可选安装词典包、有界缓存及取消。读音/辅助码/英文释义使用不同语义字段；显示释义不自动选译文。若提供译文上屏，必须明确动作并重新检查目标。网络翻译只能主动触发，不在每键候选刷新中自动外送。

**验收**：“水杉”的本地释义可查看，但普通选词仍上屏“水杉”；“上屏译文”才输出明确展示的词义。缺释义不请求网络、不扩大默认候选栏高度。多义词提供来源与修改入口，不把错译当唯一答案。切候选、切输入框、禁用扩展或密码框均使请求过期；释义刷新不能把正在点击的候选换成其他词。

### A16 · 公开市场与扩展不成为打字依赖

**独立实现**：为父任务新建的公开市场定义版本化目录、平台/最低宿主版本、资源类型、大小、摘要、许可和依赖；把“公开数据资源”与“可执行语音插件/平台适配器”分别管理。新市场可使用读取时已有的主题/布局格式，但接入远程目录仍需实现和验收。不要要求打开现有私有仓库来安装公开主题。

**验收**：无账号读取公开目录；断网使用缓存和基础主题/布局；安装失败按 A01 恢复，不把半包登记为已安装。目录不兼容/包摘要错误/依赖缺失有明确状态；卸载当前布局回到基础布局，核心符号、光标、无障碍仍可用。更新插件网络权限单独确认，凭据不进入数据包或同步。更多双拼、五笔 98、粤拼/注音或其他语言只在具体需求成立时加入；需要新组字算法的语言不能假装一个主题 JSON 就能完成。

## 8. 延迟与质量：怎样获得可信比较

### 8.1 本次能引用的数字与不能引用的数字

- 仓库历史记录：1000 句内部整句集，全拼默认配置 Top-1 75.6%，九键 48.8%；这是织文既有报告，**本次未重跑**，不代表竞品对照、盲测泛化或用户打字任务完成率。[架构与评测](ARCHITECTURE.md)、[数据集说明](../data/eval/README.md)
- 手写文档已有同机合成扰动耗时和准确率记录，但明确不是手机持续性能或真人准确率。本报告不将其与 ML Kit 广告对比。[手写验证边界](mobile-handwriting-and-floating.md)
- `typing_latency.rs` 主要检查组合长度有界和耗时趋势；资源缺失可跳过。测试文件存在不证明真机尾延迟达标。[测试](../core/weave-engine/tests/typing_latency.rs)
- 水杉：**未得到本次测量的键到屏幕、冷启动、识别或下载延迟数据**。网站演示、帧刷新周期、代码/文档中的超时、Release 的“perf”标题和 SDK 的“近实时”描述都不是竞品延迟结果。

### 8.2 推荐实验协议

| 测量 | 起止定义 | 条件与报告 |
| --- | --- | --- |
| 首次可输入 | IME 收到显示/激活到能接收输入且候选可用 | 新安装/冷进程/暖进程分别测；记录资源准备，不把提前加载隐藏到统计外 |
| 字面反馈 | 原始触摸/硬件按键时间到该字母首次呈现 | 正式包、刷新率、触摸路径与系统调度；至少千次事件并报告 p50/p95/p99 |
| 候选反馈 | 同一输入事件到对应代次候选首次呈现 | 单音节/长句、全拼/双拼/九键、开关纠错与词库包分别测 |
| 最终提交 | 选词事件到目标编辑器实际内容变化 | 普通编辑器、WebView、聊天、终端；不能只计 `commitText` 方法返回 |
| 手写 | 最后一笔抬起到当前笔迹候选可操作 | 首次模型准备与暖识别分开；真人/合成分开，排队/推理/显示分开 |
| 下载 | 点击下载到校验及载入成功 | 总墙钟时间、有效/重复字节、换源次数与恢复步骤；含网络故障场景 |

使用同一设备、OS、功耗模式、刷新率、正式构建、宿主应用、输入集与学习状态；每组多轮，公布样本数及失败率。Android 可用 System Trace/Perfetto 区分主线程、RenderThread 和呈现截止时间；Android 官方文档支持这种定位方法。[UI jank 检测][s17] Mac 使用系统性能工具与事件/显示时间观察，不能直接比较两平台不同输入源的单次函数耗时。

**建议的织文目标**：暖机正常输入字面反馈 p95 不超过两帧（60Hz 约 33ms；120Hz 约 17ms），普通本地候选 p95 以 50ms 为初始目标；超长九键/冷加载另报，不藏进平均值。先收集真实设备基线再确认预算。慢识别故障注入期间没有主线程 Future 等待；任何性能优化仍须保证零丢键、零过期写回及取消可用。这些是拟议验收指标，既不是水杉数据，也不是织文当前承诺。

质量对比若后续获准安装竞品，可从公开 UI 输入自有测试集，分别记录新用户与学习后状态；不导出竞品词库或抓取内部数据库。用户本轮授权的公开源码阅读用于核对设计与调用链，不替代运行中的准确率和延迟测量。英文与手写需要独立任务集，不能用纯汉字无标点整句集替代。

## 9. 应保留的差异与暂缓事项

### 9.1 保留织文已有方向

- 基本拼音、英文原文、候选、纠错、动态学习/撤销、组合与文档编辑、符号、无障碍和敏感字段守卫始终可用。不能让市场故障阻断打字。
- 原文英文优先、Mac 默认英文直通、点英文候选不自动加空格是当前明确行为。提高英文召回应保留这些控制权。[英文说明](learning-and-english.md)
- 云端热词是签名词表下载，本机解码；水杉的云候选是发送正在输入的拼写取远端候选，两者不是同一功能。不能把织文“不上传输入换候选”误写成“缺少云功能”。[织文架构](ARCHITECTURE.md)、[水杉隐私][s07]
- 手写与五笔在当前市场属于可选方案；保留这种入口取舍，但取消、目标代次、错误恢复与候选安全是核心责任。[扩展边界](extensions.md)
- 手机与电脑直连、独立离线翻译适配和自定义语音插件已有自己的场景价值。无需为对齐竞品账号功能改成默认中心化同步。[互联](cross-device.md)、[离线翻译](offline-translation-plugins.md)、[插件宿主](plugin-host.md)

### 9.2 暂缓，直到需求与收益成立

| 项目 | 暂缓理由 | 将来放在哪里 |
| --- | --- | --- |
| 每个候选默认在线翻译 | 增加网络、隐私与视觉负担；不能等同于中文输入质量改善 | 主动触发的翻译/词典扩展 |
| 默认 AI 回复/润色/整句云改写 | 需要上下文、费用与误改控制；不解决基础候选编辑 | 可选插件，确认后写回 |

| 照搬六套辅助码与所有语言 | 维护/许可/学习成本高；未证明用户群需要 | 一个辅助码试点、按需方案包 |
| 为每方案拆独立安装包 | 增加更新、签名、文档与数据迁移组合 | 先优化单包与按需内容；确有分发需求再做 |
| 默认云账号、遥测、云剪贴板 | 基础输入不需要账号；中心化能力增加维护成本 | 有明确同步任务才设计 opt-in 扩展 |
| Mac 默认屏幕键盘或 MCP 工具 | 与当前中文输入目标相关性较低 | 有具体辅助使用需求再评估 |

## 10. 推荐执行顺序与完成定义

1. **先把当前能力交付可靠**：A01/A03/A04，加 A02 的慢任务验证；明确哪些功能在工作区、哪些在正式包。公共市场创建不替代客户端下载验收。
2. **围绕输入成本改善**：A05 中英混输与 A06 以词取字，接着 A07 组合编辑、A08 实体键盘导航。先用自有任务集证明少切换、少删除、少翻页。
3. **让能力对更多用户可用**：A09 全文/读屏、A10 纠错误改、A11 Mac 下载、A12 真人手写、A13 连续布局场景。
4. **按数据扩展**：A14 辅助码试点、A15 本地释义、A16 公共市场内容。只扩已经证明能完成具体任务的功能。

每项完成需有：明确平台与包版本、代码位置、实际运行的验收记录、失败样本和回退行为。P0 风险未复现时记录检查结果；不要为了完成清单引入无收益改动。发布说明写最终行为，不把计划、SDK 能力或维护者测试声明包装成用户已得到的体验。
